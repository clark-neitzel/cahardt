Guia de Integração — Criação de Pedido pela IA (WhatsApp)

Como o assistente do WhatsApp (Antigravity/“Ana”) reconhece o cliente, monta o carrinho e cria o pedido no CA-Hardt. Tudo pela API /api/ia-consulta/v1, com a mesma chave que já usam. No ar na v1.4 — depende do próximo deploy do backend.

1. Princípio (quem se adapta a quem)

O CA-Hardt é o dono dos dados e das regras (cliente, preço negociado, vendedor, condição de pagamento, numeração, envio ao Conta Azul). O bot é consumidor e se adapta a este sistema.

  • O bot manda só o essencial: quem é o cliente (telefone), o que quer (produto + quantidade), quando (data/horário) e observações. Não manda preço, vendedor, tipo de pedido nem número — o CA-Hardt preenche.
  • Nada vira venda direto. O pedido do bot nasce na fila de aprovação da linha (Congelados ou Kit Festa) — a mesma fila do site. O faturamento aprova no painel do CA-Hardt, escolhendo o tipo (Normal/Especial/Bonificação) e a data. Só então vira Pedido real.
  • Preço: o bot recebe os preços no “pacote” da identificação só para conversar. Na hora de gravar, o servidor recalcula o preço real do cliente. O bot não envia valor.

2. Acesso

Base: https://<dominio-do-backend>/api/ia-consulta/v1

Autenticação: header x-ia-api-key: <chave> em toda requisição (a mesma já usada hoje).

Limite: 60 req/min por chave (429 se exceder). Sem chave no servidor → 503. Chave errada → 401.

Formato de toda resposta de sucesso

{
  "meta": { "versaoApi": "1.4.0", "avisos": [], "geradoEm": "2026-07-07T..." },
  "dados": { /* conteúdo do endpoint */ }
}
Regra do meta.avisos: a cada chamada (ou 1×/dia via /status), verificar se meta.avisos não está vazio. Ele avisa, com antecedência, qualquer mudança futura que exija ajuste do lado de vocês — antes de quebrar. Erros (4xx/5xx) vêm como { "error": "..." } (sem envelope).

3. Fluxo completo (Congelados)

  1. Reconhecer o cliente pelo telefone — POST /congelados/reconhecer-telefone. Volta o catálogo já com o preço do cliente, dias de entrega, condição, e agora também o “de sempre”.
  2. Montar o carrinho — usar o id de cada item do catálogo (não o nome).
  3. Criar o pedido — POST /congelados/pedido com itens:[{id,quantidade}]. Nasce AGUARDANDO na fila de aprovação.
  4. Faturamento aprova no painel do CA-Hardt (escolhe tipo e data) → vira Pedido real. Sem redigitar.

Kit Festa é igual, no POST /kitfesta/pedido (com horario, opcao por item e endereço/CEP se for entrega).

4. Endpoints usados na criação de pedido

POST/congelados/reconhecer-telefoneenriquecido v1.4

Identifica o cliente pelo telefone de quem manda a mensagem (autenticado pelo WhatsApp) — sem pedir CPF/senha.

Body: { "telefone": "5547999998888" }

Responde (em dados):

{
  "reconhecido": true,
  "cliente": { "nome": "...", "documento": "..." },
  "condicaoPadrao": { "id": "...", "nome": "...", "valorMinimo": 0, "permitePedido": true, "permiteEspecial": true },
  "diasEntrega": ["Segunda","Quarta"], "diasEntregaNums": [1,3],
  "catalogo": [
    { "id": "<congeladosProdutoId>", "produtoId": "...", "nome": "...", "unidade": "cx",
      "preco": 120.00, "imagem": "https://...", "comprado": true /* já pediu antes */ }
  ],
  "ultimoPedido": [    /* NOVO v1.4 — o "de sempre" (RF-B2), liberado pelo telefone */
    { "id": "<congeladosProdutoId>", "produtoId": "...", "nome": "...", "unidade": "cx",
      "quantidade": 2, "precoUnit": 120.00 }
  ]
}

Se o telefone não bater: { "reconhecido": false }.

POST/cliente/historico-pedidos+ comItens v1.4

Body: { "telefone": "...", "limite": 10, "comItens": true }

Com comItens:true, cada pedido também traz os itens. Sem o flag, a resposta é idêntica à de antes.

{
  "reconhecido": true,
  "cliente": { "nome": "..." },
  "pedidos": [
    { "numero": 920, "data": "...", "dataEntrega": "...", "statusEntrega": "...", "tipo": "NORMAL", "total": 177.30,
      "itens": [ { "produtoId": "...", "nome": "MINI COXINHA...", "quantidade": 15, "unidade": "PT", "precoUnit": 29.55 } ] }
  ]
}
POST/congelados/pedidonovo v1.4

Cria o pedido de Congelados na fila de aprovação. Preço recalculado no servidor.

Body:

{
  "telefone": "5547999998888",
  "itens": [ { "id": "<congeladosProdutoId do catálogo>", "quantidade": 2 } ],
  "data": "2026-07-15",            // opcional (entrega, YYYY-MM-DD; deve ser a partir de amanhã)
  "modo": "entrega",               // opcional: "entrega" | "retirada" (default entrega)
  "observacoes": "...",            // opcional
  "idempotencyKey": "uuid-do-bot", // opcional — evita duplicar em retry (ver §5)
  "visitante": { "nome": "...", "cpf": "...", "telefone": "..." }  // só se telefone NÃO reconhecido (ver §5)
}

Responde: { "numero": 123, "status": "AGUARDANDO", "total": 240.00, "id": "..." } (PENDENTE_CADASTRO se for cliente novo).

POST/kitfesta/pedidonovo v1.4

Mesmos nomes de campo que o de Congelados no que é comum (telefone, itens[].id, itens[].quantidade, data em YYYY-MM-DD, modo, observacoes, idempotencyKey, visitante), + extras do Kit Festa.

{
  "telefone": "5547999998888",
  "itens": [ { "id": "<kitFestaProdutoId>", "quantidade": 4, "opcao": "Frango" } ],
  "modo": "entrega",  "data": "2026-07-15",  "horario": "10:00",
  "enderecoEntrega": "...", "cep": "89239000",   // se entrega
  "cupomCodigo": "...",                          // opcional
  "observacoes": "...", "idempotencyKey": "uuid-do-bot",
  "visitante": { "nome": "...", "cpf": "...", "telefone": "..." }
}

Responde: { "numero": 45, "status": "AGUARDANDO", "total": 320.00, "id": "..." }

Foto do produto já existe. Todos os catálogos (/congelados/catalogo, /kitfesta/catalogo, reconhecer-telefone, meu-catalogo) já trazem a foto no campo imagem (Congelados traz também imagens[]). Não use imagemUrl — o campo é imagem.

5. Regras que importam na integração

TemaRegra
ID do produtoCada item de qualquer catálogo (reconhecimento e catálogos gerais) traz o id (congeladosProdutoId/kitFestaProdutoId). Mande itens[].id — não case por nome na hora de gravar.
PreçoO bot não envia preço. O servidor recalcula o preço real do cliente ao gravar. Os preços do reconhecimento servem só para a conversa.
Tipo do pedidoO bot não escolhe Normal/Especial/Bonificação — isso é decidido pelo faturamento na aprovação.
Cliente reconhecidoSe o telefone bate no cadastro (o caso comum), não pede nada — o CPF já vem do cadastro e o pedido nasce AGUARDANDO.
Cliente novoSó quando o telefone não é reconhecido: mandar visitante: { nome, cpf, telefone }. Nome e CPF/CNPJ são obrigatórios nesse caso (a conta do site tem o documento como chave e a nota precisa dele). Nasce PENDENTE_CADASTRO; o faturamento vincula. (No Kit Festa, se o telefone já casar com uma conta do site existente, o CPF é dispensado.)
IdempotênciaMandar idempotencyKey (um UUID por tentativa de fechamento). Se a mesma chave chegar de novo (timeout + retry), o servidor devolve o mesmo pedido em vez de criar outro.
Kit Festa — freteA taxa de entrega é “a combinar” — o total não inclui frete. A Ana avisa isso na conversa.
Kit Festa — confirmaçãoO envio automático de confirmação (nosso WhatsApp) nasce desligado para pedidos do bot — quem confirma é a Ana, para o cliente não receber duas mensagens.
SegurançaIdentificação sempre por telefone (o WhatsApp autentica o número). Nunca liberar/gravar dado sensível só com CPF/CNPJ digitado.

6. O que muda do lado do bot

  • Dois métodos novos no cliente HTTP: criarPedidoCongelados e criarPedidoKitFesta.
  • fecharPedido: em vez de só marcar “confirmado local”, chama o /pedido e usa numero/status/total que voltam. O total “oficial” passa a ser o que o CA recalcula.
  • Mapear nome → id no carrinho usando o catálogo do reconhecimento.
  • Kit Festa: capturar a opcao (sabor) por item.
  • Aprovação migra para o painel do CA-Hardt — a tela de rascunho de vocês vira monitor/espelho (acaba a redigitação).

7. Exemplos de teste (curl)

# Reconhecer + "de sempre"
curl -H "x-ia-api-key: SUACHAVE" -X POST -H "Content-Type: application/json" \
  -d '{"telefone":"5547999998888"}' https://<dominio>/api/ia-consulta/v1/congelados/reconhecer-telefone

# Histórico com itens
curl -H "x-ia-api-key: SUACHAVE" -X POST -H "Content-Type: application/json" \
  -d '{"telefone":"5547999998888","comItens":true}' https://<dominio>/api/ia-consulta/v1/cliente/historico-pedidos

# Criar pedido de Congelados (cliente reconhecido pelo telefone)
curl -H "x-ia-api-key: SUACHAVE" -X POST -H "Content-Type: application/json" \
  -d '{"telefone":"5547999998888","itens":[{"id":"<congeladosProdutoId>","quantidade":2}],"data":"2026-07-15","idempotencyKey":"abc-123"}' \
  https://<dominio>/api/ia-consulta/v1/congelados/pedido

# Criar pedido de Kit Festa (cliente novo → nome+cpf no visitante)
curl -H "x-ia-api-key: SUACHAVE" -X POST -H "Content-Type: application/json" \
  -d '{"telefone":"5547999998888","visitante":{"nome":"Maria","cpf":"12345678909"},"itens":[{"id":"<kitFestaProdutoId>","quantidade":4,"opcao":"Frango"}],"modo":"retirada","data":"2026-07-15","horario":"10:00","idempotencyKey":"xyz-789"}' \
  https://<dominio>/api/ia-consulta/v1/kitfesta/pedido

Contrato de referência: backend/docs/ia-consulta-api.md (v1.4) — regra de não remover/renomear campo sem aviso; mudança que quebra o formato exige /v2. Toda alteração é testada com curl antes de subir.
